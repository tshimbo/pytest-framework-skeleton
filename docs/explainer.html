2 · The Order Model

🏗️ What is a @dataclass?

A @dataclass tells Python: "This class is a container for data — auto-generate the boring methods."

Auto-GeneratedWhat It Does
__init__()Constructor from field declarations
__repr__()Pretty-print for debugging
__eq__()Compare two instances by field values
@dataclass
class Order:
    symbol: str              # e.g. "AAPL"
    side: Side                # BUY or SELL
    quantity: int             # number of shares
    price: float              # price per share
    order_type: OrderType     # LIMIT or MARKET
🔒 Why Enums?

Enums restrict a field to a fixed set of known values. This eliminates typo bugs.

class Side(Enum):
    BUY  = "BUY"
    SELL = "SELL"

# ✅ order.side = Side.BUY
# ❌ order.side = Side.BANANA  →  AttributeError
# ⚠️ order.side = "BUUY"       →  silent bug (no Enum = no catch)
🏭 field(default_factory=...)

Problem: Default values are evaluated once at class definition time.

# ❌ BAD — every Order shares the SAME id
order_id: str = str(uuid4())

# ✅ GOOD — lambda runs fresh for each instance
order_id: str = field(default_factory=lambda: str(uuid4()))
📊 Order Lifecycle

is_complete returns True for FILLED, CANCELLED, and REJECTED — the three terminal states.

3 · The Validator

💥 Custom Exception with field tracking 
class ValidationError(Exception):
    def __init__(self, field: str, message: str):
        self.field   = field    # "symbol", "quantity", "price"
        self.message = message  # human-readable description

Tests can assert on exc.field == "quantity" — precise, not message-matching.

🛡️ Guard Clause Pattern 
def _validate_symbol(symbol):
    if not symbol:                    # Guard 1: empty?
        raise ValidationError("symbol", "cannot be empty")
    if symbol not in VALID_SYMBOLS:   # Guard 2: unknown?
        raise ValidationError("symbol", f"unknown: {symbol}")
    # Implicit return None → symbol is valid

Each guard checks one bad case and bails immediately. This keeps the code flat — no nested if/elif/else.

⚡ Why a set for VALID_SYMBOLS?
Structure"AAPL" in xWhy
setO(1)Hash lookup
listO(n)Linear scan

At 16 symbols it's trivial. At 10,000 (real exchange), a set is essential.

5 · Fixture Scopes & Patterns

⏱️ The four fixture scopes
ScopeLifetimeUse For
sessionEntire test runDB connections, Docker containers
moduleOne test fileHTTP servers, file handles
classOne test classShared class state
functionOne test (default)Mutable objects like Order instances
← Broader = FASTER (less setup/teardown) ──────────────────────────→
← Narrower = SAFER (no shared mutable state) ─────────────────────→

  session ◄────► module ◄────► class ◄────► function
🔄 Yield fixtures (setup / teardown) 
@pytest.fixture(scope="session")
def db_connection():
    conn = connect()       # ← SETUP
    yield conn             # ← test runs here (conn injected)
    conn.close()           # ← TEARDOWN (guaranteed to run)

Code after yield always runs — even if a test fails. It's like finally.

🏭 Factory fixture pattern 
@pytest.fixture
def make_order():
    def _make_order(**kwargs) -> Order:
        defaults = {"symbol": "AAPL", "side": Side.BUY, ...}
        defaults.update(kwargs)       # Override only what you specify
        return Order(**defaults)
    return _make_order              # Return the FUNCTION, not an Order
NeedRegular FixtureFactory
One default order✅✅ make_order()
Custom symbol❌ new fixture✅ make_order(symbol="TSLA")
10 diverse orders❌ 10 fixtures✅ loop

6 · Unit Tests

🧩 Dependency injection in action 
def test_buy_order_has_correct_side(self, sample_buy_order: Order) -> None:
    assert sample_buy_order.side == Side.BUY

The test never imports conftest.py. It just names sample_buy_order in the parameter list. pytest:

  1. Sees the parameter name
  2. Looks it up in the fixture registry
  3. Calls the fixture function
  4. Passes the return value as the argument
💡 This is Dependency Injection The same pattern used by Spring, Angular, and FastAPI — but built into pytest's core.

7 · Parametrize & Marks

🔁 @pytest.mark.parametrize 
@pytest.mark.parametrize(
    "symbol, side, qty, price, order_type, expected",
    [
        ("AAPL", Side.BUY,  100, 150.0, OrderType.LIMIT,  None),       # valid
        ("AAPL", Side.BUY,  0,   150.0, OrderType.LIMIT,  "quantity"), # zero qty
        ("AAPL", Side.SELL, 100, -10.0, OrderType.LIMIT,  "price"),    # neg price
        ("",     Side.BUY,  100, 150.0, OrderType.LIMIT,  "symbol"),   # empty
        ("MSFT", Side.BUY,  2000000, 300, OrderType.LIMIT, "quantity"), # fat finger

    ids=["valid", "zero_qty", "neg_price", "empty_sym", "oversized"],

8 · Integration Tests

🌐 Live HTTP server architecture 
┌──────────────────┐                   ┌──────────────────────────┐
│   Test Function   │   HTTP POST      │   HTTPServer              │
│   (function scope) │ ─────────────►  │   (module scope,          │
│                    │                  │    background thread)     │
│                    │  ◄───────────── │                            │
│                    │   JSON response  │   received_orders: [ ]    │
└──────────────────┘                   └──────────────────────────┘

@pytest.fixture(scope="module")
def http_server():
    server = HTTPServer(("localhost", 0), Handler)  # Port 0 = random free port
    port = server.server_address[1]
    thread = Thread(target=server.serve_forever, daemon=True)
    thread.start()
    yield ("localhost", port)
    server.shutdown()

Port 0: OS picks a random available port — no conflicts in CI.

daemon=True: Thread dies if the process crashes.

Module scope: Server boots once per file, not once per test.

❌ Negative testing 
def test_invalid_json_returns_400(self, http_server):
    req = Request(url, data=b"not json", method="POST")
    try:
        urlopen(req)
        assert False, "Expected HTTP 400"
    except HTTPError as e:
        assert e.code == 400

Good tests verify the system handles bad input gracefully — not just the happy path.

9 · pytest Hooks

🪝 pytest_runtest_logreport 
def pytest_runtest_logreport(report):
    if report.when == "call":
        ts = datetime.now().strftime("%H:%M:%S.%f")[:12]
        outcome = "PASSED" if report.passed else "FAILED"
        print(f"[{ts}] {outcome} {report.nodeid} ({report.duration:.3f}s)")

Fires after every test phase. when == "call" filters to the actual test (not setup/teardown).

⚙️ pytest_configure 
def pytest_configure(config):
    config._metadata["Project"] = "pytest-framework-skeleton"

Runs once at startup. Adds metadata to the HTML report header.

11 · How pytest Discovers & Runs Tests

🔍 Discovery phase 
pytest starts
  │
  ├─ Read pyproject.toml → testpaths = ["tests"]
  ├─ Walk tests/ recursively
  ├─ Find files matching test_*.py
  ├─ Find conftest.py at each level
  ├─ Inside each file, find:
  │   ├─ Functions named test_*
  │   └─ Classes named Test* with methods named test_*
  └─ Expand @parametrize into individual items
▶️ Execution phase (per test)
SETUP
→
CALL
→
TEARDOWN
PhaseWhat Happens
SETUPResolve fixture dependencies, create fixtures, inject values
CALLRun the test function, record pass/fail/error
TEARDOWNRun code after yield, destroy function-scoped fixtures

12 · Interview Prep

🎯 Questions this project answers
Interview QuestionYour Answer
"Explain conftest.py scoping" Root conftest fixtures are available to all tests. Subdirectory conftest fixtures are scoped to that directory. pytest searches from the test file upward. First match wins.
"When would you use session vs function scope?" Session for expensive one-time resources (DB connections). Function for mutable objects. Tradeoff: speed vs test isolation.
"How do you test error handling?" pytest.raises as a context manager, then assert on the exception's structured attributes — not message strings.
"How do you handle test data?" Factory fixtures with sensible defaults. Override only what differs per test. Scales better than one fixture per scenario.
"How do you keep CI fast?" Marks (smoke/slow), parallel execution with xdist, coverage gates to catch untested code, pip caching.
"Walk me through your CI pipeline" Every PR: lint → typecheck → tests with 80% coverage gate → HTML report uploaded as artifact. Matrix tested on 3.11 and 3.12.
